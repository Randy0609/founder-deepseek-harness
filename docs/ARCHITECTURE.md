# 架构边界（设计稿）

## 目标

本仓库计划维护跨行业[任务 ERP 契约](TASK-ERP.md)及可复用的 DeepSeek Harness 插件源码；目前尚无插件实现。DSH 负责原生会话、模型调用与插件运行，企业系统负责业务事实和源头权限。任务状态与验收回执如何持久化仍待设计，不能默认由会话历史承担。

```text
企业已有系统与知识资料（事实、权限、外部动作）
    ↓ 受限接口 + 业务对象映射 + 有来源的动态上下文
任务契约与持久化记录（目标、负责人、状态、证据、验收）
    ↕ 待验证的任务接口
独立 DSH Profile + 本仓库未来的可选插件
    ↕ DSH 原生会话、工具、模型与界面
经营者和责任人：核对、批准、验收
```

公开仓库不储存任何用户 Profile、模型凭据、项目目录或会话。仓库中的配置示例只能使用合成名称和相对说明，不写维护者的本机路径。

## 公共契约与插件分工

| 方向 | 责任 | 接口与待验证点 |
|---|---|---|
| 任务契约与记录（实现形态待定） | 定义跨会话任务、状态、来源与验收回执 | 验证存储、事件、权限和恢复接口；不把会话当任务账本 |
| 企业地图与动态上下文（实现形态待定） | 以受限映射理解业务对象，并按任务取得当前资料 | 验证对象版本、指标口径、刷新状态和源头权限 |
| `ui-workbench` | 提供任务与项目的清楚入口 | 核实任务状态来源；复用官方侧栏与主区，不复制原生输入框 |
| `ui-capabilities` | 只读显示已发现的技能与插件 | 先找到当前版本可验证的数据来源，避免把安装、启用、当前会话可用混为一谈 |
| `ui-brand` | 可选的显示名称和自有标识 | 核实官方品牌位如何退出；不得影响任务和会话事实 |

第一个实现切片应跨越一条任务：定义问题、获取合成资料、形成建议、跨会话继续、由人验收。任务记录必须有明确事实来源；图标与视觉样式可替换，不构成任务能力的验收。

## “经营中枢”由哪些部分组成

“企业级经营中枢”是本项目的长期目标，不是已经存在的单个插件。面向不同行业，公共内核只定义任务与证据的契约；商品、合同、设备等字段由企业或行业配置。DSH 承担 Agent 执行与插件组合；订单、库存、账务、员工等事实与权限仍由企业原系统负责。

| 层 | 负责什么 | 本仓库可能提供什么 |
|---|---|---|
| 业务源系统 | 订单、客户、库存、总账、员工档案的原始记录与授权 | 不在公开仓库复制数据或凭据 |
| 企业地图 | 业务对象、关系、指标定义及其版本 | 通用描述契约；具体字段不写死在内核 |
| 动态上下文 | 按任务取有来源、时间范围与权限的资料 | 可选择受限只读适配器；数据仓库本身由企业持有 |
| 任务层 | 跨会话任务、状态、证据、责任人与验收 | 待验证的持久化和恢复接口；不依赖单次聊天存活 |
| DSH 工作台 | 会话、工具调用、角色视角与草稿 | UI、受限数据读取与证据展示插件 |
| 人的验收 | 复核事实、批准业务动作、追踪结果 | 审核状态与目标系统回执；不由模型自称完成 |

Profile 决定插件怎样组合，**不等同于企业的租户身份或源系统授权**。真实数据权限应在数据源与适配器上收窄；财务记账、员工处理、客户触达等写入动作要有明确责任人、权限和回读。DSH 官方[安全说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/SAFETY.md)也提醒不能把运行时自身当作唯一安全控制。

经营任务会产生过程证据、人的判断与结果回执；其中可复用的部分先成为 Context 或本体的**修订提案**，经来源核查、责任人审核与版本化后，再供后续任务引用。原始业务数据仍在源系统，任务记录保存引用与决策过程。这条反馈链是[任务 ERP 设计](TASK-ERP.md)的目标机制，当前尚未实现，也不能由模型自行宣称改善了经营结果。

### 一条可检验的最小任务

先用零售与服务企业的**合成资料**做同类经营异常核查：同一任务契约，分别映射不同业务对象和指标，输出来源、时间范围、异常、建议与待核实项，并跨会话交给人验收。未拿到资料时输出“不可得”及原因；不能用模型猜数补齐。该任务目前是验收目标，不是已实现能力。

后续才逐项扩展到知识库、数据仓库适配、业务经营、财务和人事。每加一个模块先写清输入、输出、权限、失败、停用和真实系统中的验收责任，再决定是否需要新的 DSH 插件。

## 兼容性与失败路径

研究基线是 `@deepseek-ai/dsh` `0.1.5-rc.3`，来源为本机个人实例在 2026-09-23 的安装包。它的文档描述了三栏壳、侧栏品牌位、全局面板位和右侧文件区；**本仓库尚未完成插件接入或版本兼容测试**。

每个未来的包应声明已验证的 DSH 版本，不用宽松版本范围暗示兼容。启动失败时停用该包并恢复原生界面；任何插件都不得迁移、删除或重写现有会话与模型设置。
