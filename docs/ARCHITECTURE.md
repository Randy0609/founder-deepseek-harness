# 架构边界（设计稿）

## 目标

本仓库维护可复用的 DeepSeek Harness 插件源码。插件负责呈现和可选能力，不接管 Harness 的会话、模型调用、权限与文件存储。用户的 Profile 负责安装与启用插件，项目和会话数据仍由各自的 Harness 实例管理。

```text
公开仓库：packages/<plugin>/
    ↓ 构建与版本发布（以后）
用户本地：独立 DSH Profile 中选择性挂载
    ↓ 使用现有扩展位
DSH：原生侧栏 / 主区 / 会话输入 / 右侧文件区
```

公开仓库不储存任何用户 Profile、模型凭据、项目目录或会话。仓库中的配置示例只能使用合成名称和相对说明，不写维护者的本机路径。

## 插件分工

| 模块 | 责任 | 接口与待验证点 |
|---|---|---|
| `ui-brand` | 显示可配置的品牌名称和自有标识 | 官方侧栏品牌位与会话空白页标识位；核实默认官方品牌如何退出 |
| `ui-workbench` | 提供任务与项目的清楚入口 | 官方侧栏列表和主区面板；不复制原生输入框；核实切换时草稿和项目选择 |
| `ui-capabilities` | 只读显示已发现的技能与插件 | 先找到当前版本可验证的数据来源，避免把安装、启用、当前会话可用混为一谈 |

第一个实现切片应跨越一个实际用户动作：进入工作台、发起新任务、回到原生会话；测试跨越同一接口。图标与视觉样式可替换，任务和会话事实仍来自 Harness 自己的状态。

## “经营中枢”由哪些部分组成

“企业级经营中枢”是本项目的长期目标，不是已经存在的单个插件。DSH 承担任务入口与 Agent 执行；订单、库存、账务、员工等事实与权限仍由企业原系统负责。

| 层 | 负责什么 | 本仓库可能提供什么 |
|---|---|---|
| 业务源系统 | 订单、客户、库存、总账、员工档案的原始记录与授权 | 不在公开仓库复制数据或凭据 |
| 数据与知识 | 清洗、去重、指标口径、时间范围、文档版本与来源 | 可选择受限的只读适配器；数据仓库本身由企业持有 |
| DSH 工作台 | 项目、会话、工具调用与草稿 | UI、知识检索、受限数据读取与证据展示插件 |
| 人的验收 | 复核事实、批准业务动作、追踪结果 | 审核状态与回执接口的设计；不由模型自称完成 |

Profile 决定插件怎样组合，**不等同于企业的租户身份或源系统授权**。真实数据权限应在数据源与适配器上收窄；财务记账、员工处理、客户触达等写入动作要有明确责任人、权限和回读。DSH 官方[安全说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/SAFETY.md)也提醒不能把运行时自身当作唯一安全控制。

### 一条可检验的最小任务

先用合成订单和库存数据做周经营简报：输入声明口径与日期范围，读取两份只读样例，输出指标、来源、异常和待核实项，由人验收。未拿到数据时输出“不可得”及原因；不能用模型猜数补齐。该任务目前是验收目标，不是已实现能力。

后续才逐项扩展到知识库、数据仓库适配、业务经营、财务和人事。每加一个模块先写清输入、输出、权限、失败、停用和真实系统中的验收责任，再决定是否需要新的 DSH 插件。

## 兼容性与失败路径

研究基线是 `@deepseek-ai/dsh` `0.1.5-rc.3`，来源为本机个人实例在 2026-09-23 的安装包。它的文档描述了三栏壳、侧栏品牌位、全局面板位和右侧文件区；**本仓库尚未完成插件接入或版本兼容测试**。

每个未来的包应声明已验证的 DSH 版本，不用宽松版本范围暗示兼容。启动失败时停用该包并恢复原生界面；任何插件都不得迁移、删除或重写现有会话与模型设置。
